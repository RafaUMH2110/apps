PERSONAL STATION · WEATHER UNDERGROUND / EARTH NETWORK

Your station, live and in the past

Continuous polling of your personal weather station (Vevor YT60234 or compatible), with automatic backoff, a configurable timeout and a clear warning as soon as something does not add up — plus a panel to look up any specific day in the past, not just the last 7.

Note: polling only works while this tab stays open; it is not a background process, so it stops if you close the tab or reload the page.

Glossary

Station IDThe identifier of your station on wunderground.com (My Profile → My Devices).
API KeyOptional key that some Weather Underground accounts require to read data. It is sent as a URL parameter, never as a header.
FreshnessSeconds elapsed between the moment the station recorded the reading and the current moment. If it exceeds the configured threshold, the reading is marked as obsolete ("stale").
Trend (▲ ▼ —)Compares the latest value of each variable with the previous one: it rises, falls or stays steady.
Feels-like temperatureIn hot weather (≥ 27 °C) it uses the heat index (temperature + humidity); in cold weather (≤ 10 °C with some wind) it uses the wind chill; otherwise it equals the air temperature. It is computed in the browser, with no extra API calls.
Dew pointTemperature at which air, as it cools, would become saturated with moisture and start to condense. The closer it is to the air temperature, the more humid (muggy) the air feels.
Accumulated rainTotal rain (mm) that the station itself has accumulated, normally since local midnight; it resets by itself every day in the hardware, not in this app.
Wind directionWhere the wind comes from, in degrees (0-360°, with 0°/360° = North) and as a compass point (N, NW, SE...). Because it is a circular quantity, the trend arrow can be unintuitive right when crossing 0°/360°.
BackoffGrowing wait between retries after a transient error (network, timeout, 5xx): it doubles each time, up to a configurable maximum.
Plausibility checkEach reading is compared with a physically possible range per variable; if something falls outside the range, a warning is shown before you trust the data.
X axis of the sparklines“Per reading” spaces the points uniformly; “Real time” places them inside a fixed window (number of points × polling interval) ending right now, with the start and end time of that window under the chart, bunched to the right if the history is not full and with visible gaps if there were retries.
12 / 24-hour and 7-day evolutionOptional panels (tap to expand) with longer charts than the session sparklines: they are built from a history saved in this browser (IndexedDB), which persists across reloads and sessions, unlike the table history. Both show the full history, reading by reading (not a summary). The 7-day one also tries to fill itself from the API history when the monitor starts, for the days with gaps; under that chart a warning shows whether the API history contributed anything or not (many accounts do not have that endpoint available). The 12-hour one also adds the readings recorded by the TeleMet Collector on the server, when available. Hover (or touch) any of them to see the exact value of each reading. On the hourly one, the 12 h / 24 h selector in its header changes the window shown (the choice is remembered in this browser).
Look up a specific dayUnlike the previous charts, it is not limited to the last 7 days: you pick any past date and, if what is saved in this browser does not cover the whole day, it is completed with the Weather Underground API history for that exact date. If that query returns nothing either (many accounts do not have that endpoint available), a notice is shown and only what exists locally is displayed.
