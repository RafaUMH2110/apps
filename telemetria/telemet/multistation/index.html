My stations

Each station can have its own API Key; if you leave a station’s key empty, the “shared key” below is used. The name is optional (if left empty, the name reported by the station is used).

Polling

Each station is queried separately, at its own pace and with its own retries: if one fails, the others carry on. Start-ups are staggered by a few seconds so that not all requests go out at once.

07 · Maintenance

Data and server

Synchronisation with TeleMet Collector, what is stored in this browser, and export.

Server history (TeleMet Collector)

If the collector runs on the same server, this app reads, for each station, its file history_<ID>.json (or historial_<ID>.json) and, if it does not exist, the single history.json / historial.json when its stationId matches. It only adds missing readings: it never deletes or modifies local data. If there is no collector, it is simply ignored. It synchronises on its own when the page opens and every 2 minutes; these tables update automatically.

Default data/. If there is no file there, the app also tries the usual TeleMet History/Historial folders (../telemethistory/data/, ../telemethistorial/datos/, ../history/data/ and ../historial/datos/). For any other location, type it here.

History stored in this browser

9 days are kept per station (IndexedDB). “Fill” asks the API for the days with gaps in the last 7 (one request per station and incomplete day, which counts towards your key’s limit).

Glossary

Station ID / API KeyIdentifier of each station on wunderground.com (My Profile → My Devices) and the API key. Each station can use its own; if empty, the “shared key” is used.
Independent pollingEach station has its own cycle, its own retry counter and its own state: a wrong key (401) or a non-existent Station ID (404) stops only that station.
BackoffGrowing wait between retries after a transient error (network, timeout, 5xx): it doubles each time, up to a configurable maximum.
Call limitWeather Underground keys have a daily request limit (usually 1,500 a day on personal accounts; check it in your account). With several stations sharing a key, the calls add up: the app warns you if the chosen interval exceeds it.
Status lightGreen: recent reading. Amber: the reading is older than the “stale data” threshold. Red: error or station stopped. Grey: not polling.
Trend (▲ ▼ —)Compares the station’s latest temperature with the previous one.
Comparison and differencesWith a reference station, each cell also shows the difference from it (Δ). Useful to see gradients between areas or to check one sensor against another.
Feels-like temperatureHeat index at ≥ 27 °C, wind chill at ≤ 10 °C with some wind; otherwise, the air temperature. Computed in the browser.
Dew pointTemperature at which the air would become saturated with moisture. The closer it is to the air temperature, the more humid it feels.
Accumulated rainTotal the station itself has accumulated, normally since local midnight; it resets by itself every day in the hardware.
Overlaid chartsEach line is a station. To save points, data is grouped into 3 min (12 h), 5 min (24 h) or 30 min (7 d) intervals and their average is shown. Long gaps without data are not joined with a straight line.
Browser historyEvery reading is stored in IndexedDB (9 days per station). It persists between sessions in this same browser and device.
TeleMet CollectorPython program on the server that reads the stations even when nobody has the app open and publishes one JSON per station. This app reads them and adds the readings it is missing.
Schematic mapPosition of the stations according to the coordinates they report, over an OpenStreetMap background (it can be turned off; without a connection it works without the background). North is up.
